통합17건은 정형 SQL8개, 실제 NL2SQL2개, 권한 거부1개, 회원별 프로필 대조2개, 동시 조회4개임.  
NL2SQL은 자연어 질문을 모델이 SQL로 변환하는 방식임. 모델 생성 SQL은 검증 후에만 DB에서 실행됨.  
CLI/API는 각각 저장 토큰 A/B 조회, NL2SQL 조회, 인증 없는 요청 거부를 실제로 확인함.  
업무 데이터 행, 비밀번호, 인증 토큰과 회원 ID는 시험 보고서에 저장하지 않음.

이번 보완에서는 통합시험과 카탈로그 및 최대 응답 시험을 실행함.  
CLI/API8건은 동일 서비스 코드와 저장 설정으로 이전 최종 실행에서 통과한 증거를 유지함.

## 실제 조회와 시간 예산

최악값은 단계에 배정한 최대 예상 시간임. 이번 실측은 실행한 표본의 결과이며 모든 부하의 최악값 보장은 아님.

| 항목 | 설계 예산 | 실측 |
|---|---|---|
| 정형 조회8건의 전체 경로 | 경로14초, 요청30초 | 0.0323초부터 1.1459초 |
| NL2SQL2건의 전체 경로 | 경로29초, 요청30초 | 0.8051초, 0.7895초 |
| Groq 호출 | 각15초, 재시도0회 | 0.767896초, 0.746126초 |
| DB 단계 S-R5 | 8초 | 최대1.142850초 |
| 실제 조회의 S-R6 | 1초 | 최대0.000107초 |
| 합성 최대 결과 S-R6와 추가 JSON 인코딩 | 1초 | 최대0.00275312초 |
| CLI NL2SQL, 프로세스 시작 포함 | 요청30초 | 1.5447초, 이전 실제 진입점 검증 |
| API NL2SQL, HTTP 포함 | 요청30초 | 0.8494초, 이전 실제 진입점 검증 |

각 실행 단계가 배정된 상한 안에 종료했는지 시험 코드에서 판정하여 모두 통과함.  
정형8건과 거부 요청은 모델 호출0회, NL2SQL2건은 각각1회로 확인함.  
실제 모델 응답은 finish_reason=stop 및 스키마 검사를 통과함. 이번2건은 승인된2048토큰 설정 안에서 완결됨.

S-R6 벤치마크는 합성200행, QueryResult 1,048,575바이트를 사용함.  
1MiB 한도는 QueryResult에 적용됨. 외부 응답 필드 포함 JSON은 1,048,877바이트로 별도 기록함.  
finish는 동기 함수이며 CPU 작업을 강제 중단하는 실시간 실행기는 아님. 표본5회가 1초 이내임을 확인한 결과임.

## 뷰 목록과 회원 범위 검증

공개 app 뷰8개와 app_internal 뷰4개가 설계 당시 카탈로그와 일치함.  
설계에만 있는 뷰, DB에만 있는 뷰, 컬럼과 접근 변경은 모두0개임.  
내부 뷰는 모델 조회 허용 목록에 포함되지 않음. LIMIT 0으로 데이터 행 없이 접근 가능 여부를 검사함.

회원 A/B의 프로필을 해당 회원의 원본 행과 메모리에서 대조함.  
같은 워크플로우에서 A/B/A/B를 동시에 호출한4건도 각각 해당 회원의 프로필과 일치함.  
이는 시험한 회원 프로필의 세션 격리 증거임. 모든 회원과 모든 뷰의 정확성을 일반화한 증명은 아님.  
cardlab 시험이므로 제한 계정의 DB 권한과 RLS 자체의 강제성은 별도 운영 검증 범위임.  
RLS는 DB가 회원 권한에 따라 보이는 행을 제한하는 기능임.

## 재실행 방법

가상환경 활성화 후 crc/sql-retriever에서 아래 명령으로 같은 검증을 재현 가능함.

```bash
python run_catalog_checks.py
python run_integration.py
python run_entrypoint_tests.py
python run_response_benchmark.py
python -m pytest -q
```

catalog_checks는 읽기 전용 메타데이터 검사임. response_benchmark와 pytest는 외부 호출이 없음.  
integration과 entrypoint_tests는 실제 DB와 승인된 Groq를 호출하며 저장된 토큰을 사용함.  
HTTP 시험 서버는 자동 종료됨. loaded_at24시간 유효성은 유지하므로 다음 날 재실행 시 기준정보 재확인 필요함.

## 설계 결정과 구현 범위

- schema_catalog는 PPT의 object 계약에 맞춰 View 이름을 키로 사용함
- 인증은 서버의 Bearer token 매핑으로 AuthScope 생성, 요청 본문의 회원 범위는 거부함
- Q-04의 period는 null, 실제 월은 결과 행의 base_month/as_of_date로 전달함
- Context7 미제공은 승인된 공식 문서 대체로 처리하고 dev_plan.md에 출처 기록함
- 연결은 요청마다 생성하고 폐기하며 최대8개 연결과 대기1초를 적용함
- SQL은 미한정 승인 함수와 고정 search_path 사용, 명시적 pg_catalog 함수 표기는 거부함
- 슬롯에 집계 후 조건 표현이 없어 HAVING은 보수적으로 거부함
- 등록 동의어와 명시적 지표/기간 중심으로 지원하며 불명확한 조건은 명확화 오류로 처리함
- 월별 View의 임의 월중 기간과 모델이 덧붙인 필터는 거부함
- HTTP 본문 수신은 최대5초, 업무30초 예산은 본문 수신 후 적용함
