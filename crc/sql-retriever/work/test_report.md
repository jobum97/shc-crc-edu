pytest는 가짜 DB와 모델을 사용함. 실제 DB 조회 성공을 의미하지 않음.  
API 성공 경로는 TestClient와 가짜 포트로 검사함. 실제 HTTP 서버에서는 인증 실패 경로만 확인함.  
CLI 성공 경로는 주입한 가짜 워크플로우로 검사함. 실제 프로세스는 인증 실패 경로만 확인함.

로컬 서버의 첫 실행은 샌드박스의 포트 바인딩 제한으로 실패함.  
허용된 실행 권한으로 재실행하여 위 HTTP 응답을 확인하고 서버를 종료함.

## 검증한 동작

- 고정 질문 8개가 동일 SQL을 검사하고 모델 호출 없이 DB 포트를 한 번 호출함
- NL2SQL 질문이 모델을 한 번 호출하며 회원 범위가 전송 페이로드에 포함되지 않음
- 모호한 질문, 기간 축소, 집계 방식 변경, 추가 필터, OR 우회와 비허용 SQL 차단
- 관리자 이름 사전 차단, 연결 후 관리자 및 원본 테이블과 컬럼 권한 검사
- 읽기 전용 트랜잭션, 회원과 날짜의 매개변수 바인딩, SQL 해시 확인
- 결과 크기 초과와 취소 시 연결 정리, NULL과 숫자 정밀도 및 날짜 의미 보존
- 중복 JSON 키와 인증 범위 중복 및 잘못된 설정 거부
- 고정 오류 코드 및 HTTP 상태, 직렬화 실패 시 S-R6 오류 응답
- 남은 시간 계산 6개 예, 모델 만료 예산과 timeout, 재시도 없는 오류 종료

## 설계 시간의 검증 범위

최악값은 단계가 사용할 수 있는 최대 예상 시간임. 가짜 연동의 속도로 실제 최악값을 증명할 수 없음.

| 설계 가정 | 구현 상한 | 이번 실측과 판정 |
|---|---|---|
| 전체 업무 | 30초 | 예산 계산 시험 통과, 실제 성공 경로 시간은 미측정 |
| 정형 경로 합계 | 14초 | 가짜 연동으로 경로 확인, 실제 8건 미실행 |
| NL2SQL 경로 합계 | 29초 | 가짜 모델 1회 확인, 실제 모델 응답 시간 미측정 |
| Groq | 15초, 재시도0 | 인자와 timeout 변환 확인, 2048토큰 완결성 미검증 |
| DB | 8초 | 구간별 timeout 및 정리 시험, 실제 실행 지연 미측정 |
| SQL 실행 | 최대3초, 잔여시간에 따라 축소 | 바인딩된 statement_timeout 범위 시험 통과 |
| 실제 API 인증 오류 | 해당 없음 | 0.0142초, 성공 경로 성능의 근거로 사용하지 않음 |
| 전체 단위 회귀 | 해당 없음 | 188개 0.46초, 실제 서비스 성능과 구분함 |

S-R6 응답 구성은 동기 JSON 직렬화임. 예약한 1초 안에 마치는지 실제 최대 크기 결과로 추가 측정 필요함.  
CPU 작업은 운영체제 스케줄링 영향이 있어 벽시계의 절대 종료를 보장하는 실시간 시스템은 아님.

## 미실행 원인과 재개 방법

사전 점검에서 아래 값이 준비되지 않아 실제 DB와 Groq 호출을 수행하지 않음.

1. 비관리자 RDB_USER와 해당 RDB_PASSWORD
2. runtime.local.json의 실제 base_date, coverage_start, loaded_at
3. 서로 다른 시험 회원 범위 2개
4. 각 인증 범위와 연결된 비밀 토큰 환경변수

사용자가 README대로 로컬 설정을 채운 뒤 `python run_integration.py`로 재개 가능함.  
실제 비밀번호와 회원 ID를 대화에 게시할 필요 없음. 설정 파일은 Git 제외 대상임.  
실제 카탈로그 일치, 정형 SQL 8건, 실제 NL2SQL 및 두 회원 실행 성공 여부는 아직 확인하지 않음.  
두 회원의 결과가 권한에 맞는지 정답 데이터와 비교하는 격리 검증도 남아 있음.

현재 run_integration.py는 공개 뷰의 컬럼 이름과 타입 및 접근 가능 여부를 비교함.  
그 외 내부 뷰 가시성 차이의 전체 목록은 수집하지 않으며 실제 시험 시 추가 검토 대상임.

## 설계의 구체화와 지원 제한

사용자 “구현까지 진행해줘”를 앞서 제시한 기본안과 공식 문서 대체 및 구현 승인으로 기록함.

- schema_catalog: PPT의 object 계약으로 구현, View 이름을 키로 사용함
- 인증: 로컬 Bearer token 매핑으로 AuthScope 생성, 본문 회원 범위는 거부함
- 기준일: 관리 설정의 명시값 사용, loaded_at 기준 24시간 유효 정책 적용함
- Q-04: Plan과 결과의 period는 null, 실제 월은 결과 행으로 전달함
- Context7 미제공: 공식 문서로 대체하고 dev_plan.md에 출처 기록함
- 연결: 풀 재사용 대신 요청별 연결, 최대8개 세마포어와 1초 대기 적용함
- SQL: 명시적 pg_catalog 함수 표기는 거부, 미한정 승인 함수와 고정 search_path 사용함
- SQL: 슬롯에 집계 후 조건 표현이 없어 HAVING을 거부함. 설계의 문법 허용 범위보다 좁음
- 질문: 등록된 동의어와 명시적 지표 및 기간에 한정함. 불명확한 조건은 명확화 오류로 처리함
- 월별 View: 임의 월중 기간을 월 단위로 반올림하여 다른 금액으로 답하지 않도록 거부함
- HTTP 본문: 16KiB 및 수신5초 한도 적용, 업무 예산은 수신 후부터 계산함

승인 원본 프롬프트와 정형 SQL 리소스는 유지함. 위 보수적 제한은 더 넓은 SQL을 실행하도록 바꾸지 않음.
