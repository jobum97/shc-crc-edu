# 연회비 상담 설계 독립 출처 점검

검토 역할: 법령 조사관 법원이  
검토 대상: 교육용 DB 자료와 새 논리 뷰·정형쿼리의 출처 및 실행 증거  
검토 방법: 저장소 파일 직접 대조. 실제 법령 조사와 DB 명령 재실행은 제외

## 확인된 사실

- 고객군: `crc/rdb/init/01_schema.sql` 17~24행. `segment_id=6`은 연회비 부담 고객군.  
- 상담 이력 고객: `crc/rdb/README.md` 6~29행. `M-6001`, `M-6049`는 세그먼트 6 고객.  
- 검증 예시 고객: `crc/rdb/init/02_seed.sql` 578, 2040~2041행.  
  `M-6074`도 세그먼트 6이며 활성 카드 2장 보유.  
- 자료 시점: `crc/rdb/init/01_schema.sql` 1~5, 30~38행과 `02_seed.sql` 87135~87142행.  
  거래 기준일은 2026-08-31, 상품 자료 시행일은 2027-01-15.  
- 연회비 단위: `crc/rdb/init/01_schema.sql` 42~54, 65~75행.  
  `(product_id, brand)` 조합별 총연회비 안내값.  
- `M-6074` 연회비: `crc/rdb/init/02_seed.sql` 713~714, 798~799, 2040~2041행.  
  카드별 안내값은 각각 32,000원과 52,000원.  
- 거래 상태: `crc/rdb/init/01_schema.sql` 77~85행.  
  `APPROVED`와 `CANCELLED`는 구분되며 취소 건은 승인 합계 제외.  
- 기준 기간: `crc/rdb/README.md` 139~145, 199~211행.  
  예제의 거래 제공 시작일은 2025-08-01, 기본 조회는 기준월 포함 최근 6개월.

## 뷰와 쿼리 의미 점검

- `crc/rdb/init/07_card_fee_usage.sql` 36~48행: 기존 카드 뷰와 요청 범위를 이용하며,  
  최근 6개월 첫날·제공 시작일·카드 발급일 중 가장 늦은 날부터  
  `APPROVED` 거래만 집계함.  
- 같은 파일 17~35, 49~61행: 실제 관측 시작일이 기준일 뒤이면 기간·금액·건수는 `NULL`임.  
  관측 가능한 기간에 승인 거래가 없으면 금액·건수는 0임.  
  달 수는 거래 여부가 아닌 관측 월 수임.  
- 같은 파일 8, 36, 63~70행: 뷰는 `security_barrier=true`, 소유자는 `app_reader`,  
  서비스 계정에는 새 뷰의 `SELECT` 권한만 추가함. 기존 회원 범위는  
  `crc/rdb/init/04_views_rls.sql` 47~67행의 RLS 정책에 의존함.  
- `crc/output/sql-retriever/assignment/Q-08.sql` 1~17행: 활성 카드만 보여 주고,  
  연회비·상품 시행일·실제 관측 기간·승인 사용액을 한 결과에서 확인 가능함.  
  주문 기준은 안내 연회비 내림차순과 승인 사용액 오름차순임.  
- 원본 카드 ID는 새 뷰 출력에 없음. `card_ref` 생성 방식은  
  `crc/rdb/init/04_views_rls.sql` 120~141행에 정의됨.

## 실행 증거의 범위

`crc/output/sql-retriever/assignment/db_validation.json`은 `status=passed`와 Q-08 결과 2행을 기록함.  
그 결과를 만든 `validate_db.py` 48~107행에는 뷰 소유자·권한, 기본 범위 미설정,  
두 카드, 미래 시행일, 월중 제공 시작일, 원본 승인 거래와의 합계 비교, 관측 불가 기간,  
다른 회원 범위 비교에 대한 검증 코드가 있음.

JSON만으로 볼륨 삭제·재시작 수행은 독립 증명할 수 없음. 명령 결과와 컨테이너 생성 시각은  
별도 `db_reset_receipt.json` 및 `db_init_log_excerpt.txt`에 기록함.  
최종 `validate_db.py`는 관리 계정과 제한 계정 모두에서 범위 미설정 0행을 확인함.  
두 회원의 카드별 승인 합계를 원본 거래의 독립 집계와 각각 대조함.

## 누락·반례와 의견

1. **원천 PDF 직접 대조 불가.** `crc/rdb/README.md` 306~311행은  
   `docs/D2_카드혜택안내_합성.pdf`를 상품 데이터의 유일한 출처로 지정하지만,  
   현재 저장소에서는 해당 PDF를 찾지 못함. 시드 SQL과 추출 JSON은 확인 가능하나  
   PDF 원문 대조를 완료했다고 표현하면 안 됨.  
2. **검증 고객과 상담 이력 고객의 구분 필요.** `M-6074`는 세그먼트 6의 시드 회원이지만  
   `crc/rdb/README.md` 11~24행의 상담 이력 12명에는 없음. 검증 사례를 실제 상담 원문과  
   연결하지 말고 가상 상담 시나리오라고 표시할 필요 있음.  
3. **과거 연회비 청구액으로 오인할 수 있음.** 상품 시행일이 거래 기준일보다 미래임.  
   `listed_annual_fee`는 2026-08-31 당시 청구액 증거가 아님.  
   Q-08은 두 날짜와 시행 여부를 함께 출력함.  
   응답 문구에도 이 차이를 유지할 필요 있음.  
4. **6개월 수치의 해석 제한.** 관측 월 수가 6이어도 카드 혜택 실적, 결제 청구액,  
   납부 연회비, 혜택 손익, 해지 판단은 확인 불가. `crc/rdb/README.md` 46~50행에도  
   승인 이용금액과 혜택 실적·청구금액의 차이가 명시됨.  
5. **재시작 증거 보완 권고.** Compose 명령 출력과 컨테이너 건강 상태,  
   초기화 완료 로그를 함께 보관하면 DB 재적재 완료 주장에 대한 독립 검증이 가능함.
